# v0.9.0: 脚本模式

## Context
Phase 2（自实现 UX 层）已全部完成（v0.3.0-v0.7.0），v0.8.0 完成代码格式化。Phase 3 聚焦扩展能力，v0.9.0 是 Phase 3 第二个里程碑，实现 Java 单文件脚本的直接运行体验，对标 `uv run script.py` 和 jbang。
版本类型：minor（新增功能）

## 产品边界
本阶段做什么：
- 支持 shebang 头（`#!/usr/bin/env jex` 或 `///usr/bin/env jex`）
- 支持文件内依赖声明（`//DEPS group:artifact:version`，兼容 jbang 格式）
- 支持文件内 Java 版本声明（`//JAVA 21`，可选）
- 缓存编译：首次编译后缓存 class 文件，后续直接运行（依赖/源码未变时跳过编译）
- CLI `jex run` 增强：自动检测 shebang 文件，走脚本解析流程

本阶段不做什么：
- 不重复实现 JEP 330（`java HelloWorld.java` 已能单文件直跑，jex 差异化在依赖解析+缓存）
- 不做多文件源码程序（JEP 458，留给未来里程碑）
- 不做 REPL（jshell 已覆盖，jex 聚焦文件级脚本）
- 不做热重载

## 子任务详细设计

### 1 脚本解析引擎

- **功能目标**：解析 `.java` 文件中的 shebang 和 pragma 注解，提取依赖声明和 Java 版本要求
- **文件结构**：新建 `crates/jex-core/src/script.rs`
- **接口设计**：
  ```rust
  pub struct ScriptMeta {
      pub java_version: Option<String>,  // //JAVA 21
      pub deps: Vec<String>,             // //DEPS com.google:gson:2.11.0
      pub is_script: bool,               // 有 shebang 或 pragma
  }

  pub fn parse_script(path: &Path) -> Result<ScriptMeta>;
  ```
- **解析规则**：
  - Shebang：`#!/usr/bin/env jex` 或 `///usr/bin/env jex`（第一行，以 `#!` 或 `///` 开头）
  - 依赖声明：`//DEPS group:artifact:version`（每行一个，支持多行）
  - Java 版本：`//JAVA 21` 或 `//JAVA 21+`（可选，默认使用当前 JDK）
  - 注解格式兼容 jbang（`//` 前缀，非 `///`）
- **后端流程**：读取文件前 N 行 → 正则匹配 shebang/pragma → 解析依赖列表 → 返回 ScriptMeta
- **测试标准**：单元测试覆盖各种 shebang/pragma 组合、无 shebang 文件、格式错误容错
- **提交信息**：`feat(script): add script parser with shebang and pragma support`

### 2 缓存编译

- **功能目标**：首次编译后缓存 class 文件，依赖列表或源码未变时跳过编译直接运行
- **文件结构**：修改 `crates/jex-core/src/run.rs`（集成缓存逻辑）
- **接口设计**：
  ```rust
  pub struct CompileCache {
      pub deps_hash: String,    // 依赖列表的哈希
      pub source_hash: String,  // 源码内容的哈希
      pub class_dir: PathBuf,   // 缓存的 class 目录
  }

  pub fn get_or_compile(script_path: &Path, meta: &ScriptMeta, config: &FmtConfig) -> Result<PathBuf>;
  ```
- **缓存策略**：
  - 缓存目录：`~/.jex/cache/scripts/{source_hash}/`
  - 缓存键：依赖列表 SHA256 + 源码 SHA256
  - 缓存命中：class 目录存在且未过期 → 直接返回 class 目录
  - 缓存未命中：下载依赖 → 编译 → 写入缓存
- **后端流程**：计算缓存键 → 检查缓存 → 未命中时下载依赖+编译 → 写入缓存 → 返回 class 目录
- **测试标准**：单元测试覆盖缓存键计算、缓存命中/未命中逻辑
- **提交信息**：`feat(script): add compile cache with content-based invalidation`

### 3 CLI `jex run` 增强

- **功能目标**：`jex run script.java` 自动检测 shebang 文件，走脚本解析流程
- **文件结构**：修改 `crates/jex-cli/src/main.rs`（Run 命令增强）
- **接口设计**：
  ```rust
  // jex run script.java  —— 自动检测 shebang，走脚本模式
  // jex run src/Main.java —— 非脚本文件，走原有编译流程
  // jex run -- —— 保持原有行为
  ```
- **检测逻辑**：
  - 读取文件第一行，匹配 `#!` 或 `///` 开头 → 脚本模式
  - 否则 → 原有编译流程（向后兼容）
- **后端流程**：解析参数 → 检测 shebang → 调用 parse_script → 调用 get_or_compile → 运行 class
- **测试标准**：CLI 集成测试（shebang 文件检测、非脚本文件回退）
- **提交信息**：`feat(cli): enhance jex run with script mode detection`

### 4 集成测试 + 文档

- **功能目标**：端到端测试脚本模式，更新产品文档

- **提交信息**：`test(script): add integration tests for script mode`
