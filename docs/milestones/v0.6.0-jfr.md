# v0.6.0: JFR 自解析

## Context
v0.5.0 完成了 async-profiler 火焰图捆绑，实现了 `jex java flame`。v0.6.0 继续完善 JVM 诊断能力，实现 Java Flight Recorder (JFR) 的录制控制与事件解析。JFR 是 JDK 内置的低开销采样分析器，提供比火焰图更丰富的事件维度（CPU 热点、GC 详情、I/O 等待、锁竞争、内存分配），是生产环境性能分析的核心工具。
版本类型：minor（新功能）

## 产品边界

### 做什么
- `jex java rec <pid>`：启动/停止 JFR 录制，dump .jfr 文件，终端展示摘要
- `jex java analyze <file.jfr>`：离线分析 .jfr 文件，按事件类型展示结构化表格
- 支持的事件类型：CPU 采样、GC 事件、I/O（文件/网络）、线程阻塞、内存分配
- 纯 Rust 实现，不依赖 JDK 的 `jfr` 命令行工具

### 不做什么
- 不做 JFR 事件的深度关联分析（如火焰图叠加 JFR 数据）
- 不做 Web UI 可视化
- 不做持续实时 JFR 流式展示（留给 2.5 诊断增强）
- 不支持 Windows（JFR 在 Windows 上需要额外配置）

## 子任务详细设计

### 1 JFR 录制生命周期控制

- **功能目标**：通过 `jcmd` 控制目标 JVM 进程的 JFR 录制
- **文件结构**：新建 `crates/jex-core/src/jfr.rs`，修改 `crates/jex-core/src/lib.rs`、`crates/jex-cli/src/main.rs`
- **接口设计**：
  ```rust
  /// JFR 录制会话
  pub struct RecordingSession {
      pid: u32,
      output_path: PathBuf,
      duration_secs: Option<u32>,
  }

  /// 启动 JFR 录制
  pub fn start_recording(pid: u32, duration_secs: Option<u32>) -> Result<RecordingSession>;

  /// 停止并 dump JFR 文件
  pub fn dump_recording(session: RecordingSession) -> Result<PathBuf>;

  /// 列出目标 JVM 支持的 JFR 事件类型
  pub fn list_event_types(pid: u32) -> Result<Vec<String>>;
  ```
- **后端流程**：
  1. 检测 JDK 路径（复用 `jex jdk which` 的路径查找）
  2. 执行 `jcmd <pid> JFR.start filename=<path> duration=<s> settings=profile`
  3. 等待录制完成后执行 `jcmd <pid> JFR.dump filename=<path>`
  4. 返回 .jfr 文件路径
- **测试标准**：单元测试覆盖参数构造、错误处理（进程不存在/JFR 不可用）；mock jcmd 输出验证解析
- **提交信息**：`feat(jfr): add JFR recording lifecycle control via jcmd`

### 2 JFR 二进制解析引擎

- **功能目标**：解析 .jfr 二进制文件，提取结构化事件数据
- **文件结构**：新建 `crates/jex-core/src/jfr/parser.rs`，修改 `crates/jex-core/src/jfr/mod.rs`
- **接口设计**：
  ```rust
  /// JFR 事件类型枚举
  pub enum EventType {
      CpuSampling,      // jdk.ExecutionSample
      GcEvent,          // jdk.GarbageCollection
      FileIo,           // jdk.FileRead / jdk.FileWrite
      NetworkIo,        // jdk.SocketRead / jdk.SocketWrite
      ThreadBlock,      // jdk.ThreadLock
      MemAlloc,         // jdk.ObjectAllocationInNewTLAB / jdk.ObjectAllocationOutsideTLAB
  }

  /// 解析后的 JFR 事件
  pub struct JfrEvent {
      pub timestamp: u64,       // 纳秒
      pub event_type: EventType,
      pub duration: u64,        // 纳秒
      pub details: EventDetail,
  }

  pub enum EventDetail {
      CpuSample { thread: String, frames: Vec<String> },
      GcEvent { name: String, cause: String, threads: u32 },
      FileIo { path: String, bytes: u64, duration: u64 },
      NetworkIo { host: String, bytes: u64, duration: u64 },
      ThreadBlock { thread: String, blocking: String, duration: u64 },
      MemAlloc { class: String, size: u64, thread: String },
  }

  /// 解析 .jfr 文件
  pub fn parse_jfr(path: &Path) -> Result<Vec<JfrEvent>>;
  ```
- **后端流程**：
  1. 读取 .jfr 文件头部，验证 magic number（`FLR\0`）
  2. 解析 chunk 元数据（JDK 版本、时区、起始时间）
  3. 逐 chunk 解析事件记录，按 event type 分类提取
  4. 对于压缩 chunk（LZ4），先解压再解析
- **测试标准**：构造最小 .jfr 文件（已知事件序列）验证解析正确性；测试损坏文件的错误处理
- **提交信息**：`feat(jfr): add binary JFR parser with event extraction`

### 3 JFR 事件终端展示

- **功能目标**：将解析后的 JFR 事件以结构化表格形式展示在终端
- **文件结构**：修改 `crates/jex-core/src/jfr/parser.rs` 添加聚合逻辑，新建 `crates/jex-core/src/jfr/display.rs`
- **接口设计**：
  ```rust
  /// 汇总统计
  pub struct JfrSummary {
      pub duration_secs: f64,
      pub event_counts: HashMap<String, usize>,
      pub top_cpu_hotspots: Vec<(String, usize)>,
      pub gc_events: Vec<GcEvent>,
      pub io_summary: IoSummary,
      pub mem_allocations: Vec<AllocSummary>,
  }

  /// 统计聚合
  pub fn summarize(events: &[JfrEvent]) -> JfrSummary;

  /// 终端展示
  pub fn display_summary(summary: &JfrSummary);
  pub fn display_cpu_hotspots(summary: &JfrSummary, top_n: usize);
  pub fn display_events(events: &[JfrEvent], filter: Option<EventType>);
  ```
- **后端流程**：
  1. 按事件类型聚合，计算各维度统计
  2. CPU 热点：按调用栈频率排序取 top N
  3. GC 事件：列出每次 GC 的耗时和停顿
  4. I/O 汇总：读写总量、平均延迟、热点文件
  5. 内存分配：按类型汇总分配量
- **测试标准**：对已知事件序列验证聚合结果正确性；终端输出格式验证
- **提交信息**：`feat(jfr): add terminal display for JFR event summary`

### 4 CLI 集成 + e2e 测试

- **功能目标**：完成 `jex java rec` 和 `jex java analyze` 命令的 CLI 接入
- **文件结构**：修改 `crates/jex-cli/src/main.rs`
- **接口设计**：
  ```
  jex java rec <pid>              # 交互式录制（Ctrl+C 停止 + dump + 展示摘要）
  jex java rec <pid> --duration 30  # 定时录制 30 秒
  jex java rec <pid> --output /path/to/recording.jfr  # 指定输出路径
  jex java analyze <file.jfr>     # 离线分析 .jfr 文件
  jex java analyze <file.jfr> --type cpu  # 只展示 CPU 事件
  jex java analyze <file.jfr> --top 10  # 展示 top 10 热点
  ```
- **后端流程**：
  1. `rec` 命令：调用 `start_recording` → 等待（duration 或 Ctrl+C）→ `dump_recording` → `summarize` → `display_summary`
  2. `analyze` 命令：`parse_jfr` → `summarize` → `display_events`（按 --type 过滤）
  3. Ctrl+C 处理：捕获 SIGINT，优雅停止录制并 dump
- **测试标准**：单元测试覆盖 CLI 参数解析、输出格式；集成测试验证录制→解析→展示全链路
- **提交信息**：`feat(cli): integrate jex java rec and analyze commands`
