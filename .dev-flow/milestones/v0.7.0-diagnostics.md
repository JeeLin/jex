# v0.7.0: 诊断增强

## Context
v0.6.0 完成了 JFR 自解析（录制/解析/展示）。v0.7.0 继续完善 JVM 诊断能力，实现尚未完成的 Heap 堆概览和 Top 实时面板，同时增强线程分析。至此 `jex java` 子命令集（gc/threads/heap/flame/rec/analyze/top）将全部可用。
版本类型：minor（新功能）

## 产品边界

### 做什么
- `jex java heap <pid>`：堆概览（堆大小、使用率、区域分布、GC 摘要）
- `jex java top <pid>`：实时面板（CPU/内存/GC/线程 持续刷新）
- 增强线程分析：线程状态分布、死锁检测、热点线程
- 改进 GC 展示：增加 GC 暂停时间趋势

### 不做什么
- 不做分布式追踪（非 JVM 范畴）
- 不做 Profiling（已有 flame/rec）
- 不做 Web UI 可视化

## 子任务详细设计

### 1 Heap 堆概览

- **功能目标**：展示 JVM 堆内存使用情况
- **文件结构**：修改 `crates/jex-core/src/diag.rs`
- **接口设计**：
  ```rust
  /// 堆概览数据
  pub struct HeapOverview {
      pub heap_used: u64,      // bytes
      pub heap_max: u64,       // bytes
      pub heap_committed: u64, // bytes
      pub non_heap_used: u64,
      pub eden_used: u64,
      pub survivor_used: u64,
      pub old_gen_used: u64,
      pub meta_space_used: u64,
      pub gc_count: u64,
      pub gc_total_pause_ms: f64,
  }

  /// 获取堆概览
  pub fn heap_overview(pid: u32) -> Result<HeapOverview>;

  /// 终端展示堆概览
  pub fn display_heap(overview: &HeapOverview);
  ```
- **后端流程**：
  1. 执行 `jcmd <pid> GC.heap_info` 获取堆区域大小
  2. 执行 `jstat -gc <pid>` 获取各区使用量
  3. 汇总计算使用率
- **测试标准**：单元测试覆盖解析逻辑；mock jcmd 输出
- **提交信息**：`feat(diag): add heap overview via jcmd GC.heap_info`

### 2 Top 实时面板

- **功能目标**：持续刷新展示 JVM 进程关键指标
- **文件结构**：修改 `crates/jex-core/src/diag.rs`
- **接口设计**：
  ```rust
  /// 实时快照
  pub struct TopSnapshot {
      pub cpu_usage: f64,       // 进程 CPU%
      pub heap_used_pct: f64,   // 堆使用%
      pub gc_count: u64,
      pub gc_pause_ms: f64,     // 上次 GC 暂停
      pub thread_count: usize,
      pub daemon_count: usize,
      pub timestamp: u64,
  }

  /// 获取实时快照
  pub fn top_snapshot(pid: u32) -> Result<TopSnapshot>;

  /// 持续刷新展示（Ctrl+C 退出）
  pub fn top_tui(pid: u32) -> Result<()>;
  ```
- **后端流程**：
  1. 每 1 秒采集一次快照
  2. 通过 ANSI 转义码清屏重绘（复用 crossterm）
  3. 展示 CPU/堆/GC/线程实时数据
- **测试标准**：单元测试覆盖快照采集
- **提交信息**：`feat(diag): add top real-time panel for JVM processes`

### 3 增强线程分析

- **功能目标**：提供更详细的线程诊断
- **文件结构**：修改 `crates/jex-core/src/diag.rs`
- **接口设计**：
  ```rust
  /// 线程详情
  pub struct ThreadDetails {
      pub total: usize,
      pub runnable: usize,
      pub waiting: usize,
      pub blocked: usize,
      pub sleeping: usize,
      pub deadlocked: bool,
      pub deadlocked_threads: Vec<String>,
      pub top_by_cpu: Vec<(String, f64)>, // 线程名 + CPU%
  }

  /// 获取线程详情
  pub fn thread_details(pid: u32) -> Result<ThreadDetails>;

  /// 终端展示线程详情
  pub fn display_thread_details(details: &ThreadDetails);
  ```
- **后端流程**：
  1. 执行 `jcmd <pid> Thread.print -l` 获取详细线程信息
  2. 解析线程状态统计
  3. 检测死锁（`jcmd <pid> Thread.print -e`）
  4. 通过 jstack 或 perf 采样获取线程 CPU 占用
- **测试标准**：单元测试覆盖状态解析和死锁检测
- **提交信息**：`feat(diag): enhance thread analysis with deadlock detection`

### 4 CLI 集成 + e2e 测试

- **功能目标**：完成 `jex java heap` 和 `jex java top` 命令的 CLI 接入
- **文件结构**：修改 `crates/jex-cli/src/main.rs`
- **接口设计**：
  ```
  jex java heap <pid>          # 堆概览
  jex java top <pid>           # 实时面板（Ctrl+C 退出）
  jex java threads <pid>       # 增强线程详情（已存在，扩展输出）
  ```
- **后端流程**：
  1. `heap` 命令：调用 `heap_overview` → `display_heap`
  2. `top` 命令：调用 `top_tui`（持续刷新）
  3. `threads` 命令：扩展输出线程详情
- **测试标准**：单元测试覆盖 CLI 参数解析
- **提交信息**：`feat(cli): integrate heap and top commands`
