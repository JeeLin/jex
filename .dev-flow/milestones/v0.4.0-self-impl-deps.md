# v0.4.0: 依赖解析内嵌

## Context
v0.2.0 完成了 Phase 1 整合版（所有功能通过 shell 调用 cs CLI）。v0.3.0 完成了 workspace 拆分（jex-core + jex-cli）和诊断结构化。v0.4.0 是 Phase 2「自实现 UX 层」的第二个里程碑：**将所有 `Command::new("cs")` 替换为 Rust 原生依赖解析**，消除对 cs CLI 的运行时依赖。

版本类型：minor（新增功能：原生依赖解析能力）

Start Commit: 9014c6989cc5820b816e804b30c84e1ced571924

## 产品边界

**本阶段做什么：**
- 用 Rust 原生 HTTP + JSON 解析替换 cs shell 调用
- 保持所有现有命令（add/remove/update/search/run）的外部行为不变
- 添加依赖树（`jex tree`）可视化（PRODUCT.md 用户可见流程 #4）
- 移除 `ensure_cs()` 和 cs CLI 下载逻辑

**本阶段不做什么：**
- 不内嵌 Coursier JVM 库（避免 JVM 依赖）
- 不做火焰图/JFR/诊断增强（留给后续里程碑）
- 不改动 JDK 管理 / 诊断模块（不涉及 `jdk.rs` / `diag.rs`）

## 子任务详细设计

### 1 原生依赖解析核心模块（resolver.rs）

- **功能目标**：创建 `crates/jex-core/src/resolver.rs`，提供不依赖 cs CLI 的 Maven Central 依赖解析能力
- **文件结构**：新建 `crates/jex-core/src/resolver.rs`，修改 `crates/jex-core/src/lib.rs`
- **接口设计**：
  ```rust
  /// 解析给定坐标的最新版本（通过 Maven Central search API）
  pub fn resolve_latest(coord: &str) -> Result<String>;
  
  /// 解析依赖的传递闭包（通过 Maven Central POM 解析）
  pub fn resolve_dependencies(coord: &str) -> Result<Vec<DepNode>>;
  
  /// 依赖树节点
  pub struct DepNode {
      pub coord: String,
      pub version: String,
      pub children: Vec<DepNode>,
  }
  ```
- **后端流程**：
  1. 解析 `group:artifact` 坐标，调用 Maven Central search API 获取最新版本
  2. 下载该版本的 pom.xml，提取 `<dependencies>` 节
  3. 递归解析传递依赖（有深度限制，防止循环）
  4. 返回依赖树
- **测试标准**：单元测试覆盖 `resolve_latest` 和 `resolve_dependencies` 的正常/边界情况
- **提交信息**：`feat(resolver): add native Maven dependency resolver replacing cs CLI`

### 2 deps.rs 迁移到原生解析

- **功能目标**：将 `deps.rs` 中所有 `Command::new(&cs)` 调用替换为 `resolver::` 函数
- **文件结构**：修改 `crates/jex-core/src/deps.rs`，删除 `ensure_cs()` 调用
- **接口设计**：`init/add/remove/update` 子命令的外部接口保持不变
- **后端流程**：
  - `add`：用 `resolver::resolve_latest(coord)` 替代 `cs complete` 获取最新版本
  - `update`：遍历 jex.lock.toml 中的每个依赖，调用 `resolver::resolve_latest` 更新
  - 锁文件格式保持不变（向后兼容）
- **测试标准**：`cargo test` 全部通过，现有 lock 文件解析/生成逻辑不变
- **提交信息**：`refactor(deps): migrate from cs CLI to native resolver`

### 3 search.rs + run.rs 迁移到原生解析

- **功能目标**：search.rs 改用 `fetch_docs()` + resolver，run.rs 的 classpath 构建改用 `resolver::resolve_dependencies()`
- **文件结构**：修改 `crates/jex-core/src/search.rs` 和 `crates/jex-core/src/run.rs`
- **接口设计**：
  - `search()` / `versions()` 继续使用 Maven Central search API（已由 fetch_docs 实现，不变）
  - `run.rs` 的 classpath 构建从 `cs fetch -p <coord>` 改为调用 `resolver::resolve_dependencies()`
- **后端流程**：
  - run.rs：遍历 jex.lock.toml，对每个依赖调用 `resolve_dependencies()` 获取 jar 路径
  - 需要实现 jar 下载缓存（Maven Central jar 下载到 `~/.jex/cache/m2/`）
- **测试标准**：`cargo test` 全部通过，`jex run` 可正常运行简单 Java 项目
- **提交信息**：`refactor(search,run): complete migration from cs to native resolver`

### 4 `jex tree` 依赖树可视化

- **功能目标**：新增 `jex tree` 子命令，展示项目的完整依赖树（PRODUCT.md 用户可见流程 #4）
- **文件结构**：修改 `crates/jex-core/src/deps.rs`（新增 `tree` 函数），修改 `crates/jex-cli/src/main.rs`（新增子命令）
- **接口设计**：
  ```rust
  /// 读取 jex.lock.toml，构建依赖树并输出
  pub fn tree() -> Result<()>;
  ```
- **交互设计**：以 tree 格式展示：
  ```
  com.example:my-app:1.0
  ├─ com.google.code.gson:gson:2.11.0
  └─ org.slf4j:slf4j-api:2.0.9
     └─ org.slf4j:slf4j-api:2.0.9 (已去重)
  ```
- **测试标准**：单元测试覆盖树构建逻辑，去重/循环引用检测
- **提交信息**：`feat(deps): add 'jex tree' command for dependency tree visualization`

### 5 清理 cs 依赖 + e2e 测试 + CI 验证

- **功能目标**：移除所有 cs CLI 相关代码（ensure_cs、cs_path、cs_download_url），添加集成测试
- **文件结构**：
  - 删除 `config.rs` 中的 `ensure_cs()`、`cs_path()`、`cs_download_url()` 函数
  - 新建 `tests/integration.rs`（或在模块内添加 `#[test]` 集成测试）
- **后端流程**：
  - 验证 `cargo check --locked` / `cargo clippy -- -D warnings` / `cargo test` 全通过
  - 手动验证 `jex add` / `jex search` / `jex run` / `jex tree` 正常工作（无 cs）
- **测试标准**：cs CLI 不再被任何代码引用；所有现有测试通过
- **提交信息**：`chore: remove cs CLI dependency, all operations now native`
