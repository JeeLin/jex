## 产品边界

**本阶段做什么：**
- 捆绑 async-profiler 原生二进制（Linux x86_64/aarch64 + macOS x86_64/aarch64）

- 不做诊断增强（2.5）
- 不改动现有命令（add/remove/update/search/run/tree）

## 子任务详细设计

### 1 async-profiler 二进制捆绑与自动下载机制

- **功能目标**：创建 `crates/jex-core/src/profiler.rs`，提供 async-profiler 二进制的自动下载与缓存管理
- **文件结构**：新建 `crates/jex-core/src/profiler.rs`，修改 `crates/jex-core/src/lib.rs`、`crates/jex-core/src/config.rs`
- **接口设计**：
  ```rust
  /// 获取 async-profiler 二进制目录路径（~/.jex/profiler/{version}/）
  /// 首次调用时自动下载对应平台的 async-profiler 发行包
  pub fn profiler_home() -> Result<PathBuf>;

  /// 检查 async-profiler 是否已下载
  pub fn is_profiler_installed() -> bool;

  /// 下载并解压 async-profiler 到 ~/.jex/profiler/
  pub fn ensure_profiler() -> Result<PathBuf>;
  ```
- **后端流程**：
  1. 检测当前平台（Linux/macOS）和架构（x86_64/aarch64）
  2. 从 GitHub releases 下载 async-profiler 对应发行包（async-profiler-{version}-{os}-{arch}.zip）
  3. 解压到 `~/.jex/profiler/{version}/`，保留 `bin/asprof`（Linux）或 `bin/dtrace`（macOS）二进制
  4. 缓存版本号，避免重复下载
- **平台支持**：
  - Linux x86_64: `bin/asprof`（基于 perf_events）
  - Linux aarch64: `bin/asprof`（基于 perf_events）
  - macOS x86_64: `bin/dtrace`（基于 dtrace）
  - macOS aarch64: `bin/dtrace`（基于 dtrace）
- **测试标准**：单元测试覆盖平台检测逻辑；`cargo test` 全通过
- **提交信息**：`feat(profiler): add async-profiler auto-download and platform detection`

### 2 profiler.rs 模块实现（采样 + 火焰图生成）

- **功能目标**：实现采样启动、采样停止、火焰图生成的核心逻辑
- **文件结构**：修改 `crates/jex-core/src/profiler.rs`
- **接口设计**：
  ```rust
  /// 采样结果信息
  pub struct FlameResult {
      pub collapsed_path: PathBuf,   // collapsed 格式的中间文件
      pub svg_path: PathBuf,         // 生成的火焰图 SVG
      pub duration_secs: u32,
  }

  /// 对指定 PID 启动 async-profiler 采样
  /// duration_secs: 采样时长（秒），默认 10 秒
  pub fn profile(pid: u32, duration_secs: u32) -> Result<FlameResult>;
  ```
- **后端流程**：
  1. 调用 `ensure_profiler()` 获取 asprof 路径
  2. 生成输出文件路径：`/tmp/jex-flame-{pid}-{timestamp}/`
  3. 执行采样：
     - Linux: `asprof -d {duration} -f {output.collapsed} -o collapsed {pid}`
     - macOS: `dtrace -p {pid} -d {duration} -f {output.collapsed}`
  4. 采样完成后用 profiler 内置工具将 collapsed 转为 SVG：
     - `profiler.sh -d {output.collapsed} -o {output.svg}`
  5. 返回 `FlameResult`
- **设计原则**：
  - 采样过程中显示进度提示（10 秒采样 → 每秒打印 `.`
  - 采样完成后自动转换为 SVG
  - 使用 `/tmp/jex-flame-{pid}/` 临时目录，采样完成后可选清理
- **测试标准**：单元测试覆盖 collapsed 格式转换；`cargo test` 全通过
- **提交信息**：`feat(profiler): implement profiling and flamegraph generation`

### 3 CLI 集成 + 输出文件管理 + 浏览器自动打开

- **功能目标**：将 profiler 模块接入 CLI，完善输出文件管理和用户交互
- **文件结构**：修改 `crates/jex-cli/src/main.rs`（替换 `planned("2.3", ...)`）
- **接口设计**：
  ```bash
  jex java flame <pid>                    # 默认采样 10 秒
  jex java flame --duration 30 <pid>      # 自定义采样时长
  jex java flame --output /path/to.svg <pid>  # 指定输出路径
  ```
- **交互设计**：
  ```
  🔥 开始采样 PID 12345，时长 10 秒...
  ·········· 采样完成
  📊 火焰图已生成: /tmp/jex-flame-12345-xxx/flamegraph.svg
  🌐 正在打开浏览器...
  ```
- **后端流程**：
  1. 解析 CLI 参数（pid、duration、output）
  2. 调用 `profiler::profile()` 生成火焰图
  3. 如果指定了 `--output`，复制 SVG 到指定路径；否则使用默认路径
  4. 尝试用系统默认浏览器打开 SVG（`open` on macOS, `xdg-open` on Linux）
  5. 输出结果路径供用户手动查看
- **测试标准**：`cargo check` 无 error；`cargo clippy` 无 error；手动验证 `jex java flame` 输出
- **提交信息**：`feat(cli): integrate flamegraph command with browser auto-open`

## 设计核对点

- [ ] async-profiler 下载源使用 GitHub releases（稳定、无速率限制）
- [ ] 采样权限：Linux 需要 root 或 `kernel.perf_event_paranoid <= 2`
- [ ] 采样超时处理：进程不存在或权限不足时的友好错误信息
- [ ] 火焰图 SVG 大小：单次 10 秒采样预期 < 5MB
- [ ] 跨平台兼容：Linux/macOS 双平台支持，Windows 暂不支持（async-profiler 不支持）
- [ ] 临时文件清理：采样完成后可选清理 `/tmp/jex-flame-*/`
