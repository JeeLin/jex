# v0.8.0: 代码格式化

## Context
Phase 2（自实现 UX 层）已全部完成（v0.3.0-v0.7.0）。v0.7.0 增强了诊断能力（heap/top/线程）。Phase 3 开始于 v0.8.0，聚焦代码格式化工具。
版本类型：minor（新增功能）

## 产品边界
本阶段做什么：
- 提供 `jex fmt` 命令格式化 Java 代码
- 支持 google-java-format 规范
- 支持批量格式化（文件/目录）
- 支持 git diff 增量模式

本阶段不做什么：
- 不实现自定义格式化规则引擎（使用外部工具）
- 不提供 IDE 集成（后续里程碑）
- 不支持格式化非 Java 文件

## 子任务详细设计

### 1 格式化引擎

- **功能目标**：捆绑 google-java-format 作为格式化后端
- **文件结构**：修改 `crates/jex-core/src/fmt.rs`（新建）
- **接口设计**：
  ```rust
  pub struct FmtConfig {
      pub style: Style,        // GOOGLE/AYA/OpenJ7
      pub aosp: bool,          // AOSP 缩进风格
      pub skip_future: bool,   // 跳过 future 语法
  }
  
  pub fn format_file(path: &Path, config: &FmtConfig) -> Result<()>;
  pub fn format_code(code: &str, config: &FmtConfig) -> Result<String>;
  ```
- **后端流程**：下载 google-java-format JAR → 调用 java -jar 格式化
- **测试标准**：单元测试覆盖配置解析、格式化逻辑
- **提交信息**：`feat(fmt): add google-java-format engine`

### 2 CLI 集成

- **功能目标**：注册 `jex fmt` 子命令
- **文件结构**：修改 `crates/jex-cli/src/main.rs`
- **接口设计**：
  ```rust
  #[derive(Args)]
  pub struct FmtArgs {
      /// 要格式化的文件或目录
      #[arg(default_value = ".")]
      pub paths: Vec<PathBuf>,
      /// 检查模式（不修改文件，只报告）
      #[arg(long)]
      pub check: bool,
      /// 输出格式化后的代码到 stdout
      #[arg(long)]
      pub stdout: bool,
  }
  ```
- **交互设计**：无 TUI，纯 CLI 输出
- **后端流程**：解析参数 → 遍历文件 → 调用格式化引擎 → 输出结果
- **测试标准**：CLI 集成测试
- **提交信息**：`feat(cli): add jex fmt command`

### 3 配置支持

- **功能目标**：从 jex.toml 读取格式化配置
- **文件结构**：修改 `crates/jex-core/src/config.rs`
- **接口设计**：
  ```toml
  # jex.toml
  [fmt]
  style = "GOOGLE"      # GOOGLE/AYA/OpenJ7
  aosp = false
  skip_future = false
  exclude = ["build/", "target/"]
  ```
- **后端流程**：读取配置 → 合并默认值 → 传递给格式化引擎
- **测试标准**：配置解析测试
- **提交信息**：`feat(config): add fmt configuration support`

### 4 增量格式化

- **功能目标**：支持只格式化 git diff 中修改的文件
- **文件结构**：修改 `crates/jex-core/src/fmt.rs`
- **接口设计**：
  ```rust
  pub fn get_changed_files() -> Result<Vec<PathBuf>>;
  pub fn format_changed(config: &FmtConfig) -> Result<()>;
  ```
- **后端流程**：执行 git diff --name-only → 过滤 .java 文件 → 批量格式化
- **测试标准**：单元测试覆盖文件过滤逻辑
- **提交信息**：`feat(fmt): add incremental formatting mode`
