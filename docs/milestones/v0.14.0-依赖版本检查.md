# v0.14.0: 依赖版本检查

## Context
前序阶段 v0.13.0 完成了项目模板（jex create），帮助用户快速创建标准项目结构。本阶段新增依赖版本检查功能，帮助用户了解依赖更新情况并自动升级，保持项目依赖安全可靠。
版本类型：minor（新增功能）

## 产品边界
**做什么**：
- `jex outdated` 检查项目依赖是否有新版本可用
- `jex upgrade` 自动升级指定或全部依赖到最新版本
- 显示当前版本、最新版本、版本差异信息
- 支持升级单个依赖或批量升级

**不做什么**：
- 不自动升级（需用户确认）
- 不处理依赖冲突（由 jex add/remove 处理）
- 不检查依赖安全性漏洞（后续版本考虑）

## 子任务详细设计

### 1 版本检查核心
- **功能目标**：实现依赖版本查询和比较逻辑
- **文件结构**：`crates/jex-core/src/outdated.rs`
- **接口设计**：
  - `pub fn check_outdated() -> Result<Vec<OutdatedDep>>`
  - `pub fn upgrade_dep(coord: &str) -> Result<()>`
  - `pub fn upgrade_all() -> Result<()>`
  - `struct OutdatedDep { group, artifact, current, latest }`
- **设计要点**：
  - 读取 jex.toml 获取当前依赖
  - 查询 Maven Central 获取最新版本
  - 比较版本号找出可更新依赖
  - 升级时更新 jex.toml 和 jex.lock.toml
- **测试标准**：版本查询、版本比较、升级逻辑 3 个用例
- **提交信息**：`feat: add dependency version check and upgrade logic`

### 2 CLI 集成
- **功能目标**：注册 `jex outdated` 和 `jex upgrade` 子命令
- **文件结构**：`crates/jex-cli/src/main.rs`
- **接口设计**：
  - `jex outdated` 列出所有可更新依赖
  - `jex upgrade <coord>` 升级指定依赖
  - `jex upgrade --all` 升级全部依赖
- **设计要点**：
  - OutdatedArgs 结构体（无参数）
  - UpgradeArgs 结构体（coord 可选，--all 标志）
  - 表格输出显示当前版本和最新版本
- **测试标准**：命令解析测试
- **提交信息**：`feat: add jex outdated and upgrade CLI commands`

### 3 升级逻辑
- **功能目标**：实现依赖升级和锁文件更新
- **文件结构**：`crates/jex-core/src/outdated.rs`
- **接口设计**：
  - 单个依赖升级：更新 jex.toml 版本号，重新解析依赖
  - 批量升级：遍历所有依赖逐个升级
  - 锁文件同步：更新 jex.lock.toml
- **设计要点**：
  - 升级前检查依赖是否存在
  - 升级后重新解析依赖树
  - 保持依赖冲突处理逻辑一致
- **测试标准**：单个升级、批量升级、锁文件更新 3 个用例
- **提交信息**：`feat: implement dependency upgrade with lock file sync`
