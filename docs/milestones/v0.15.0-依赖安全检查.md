# v0.15.0: 依赖安全检查

## Context
前序阶段 v0.14.0 完成了依赖版本检查（jex outdated/upgrade），帮助用户了解依赖更新情况并自动升级。本阶段新增依赖安全检查功能，帮助用户发现项目依赖中的已知安全漏洞，提升项目安全性。
版本类型：minor（新增功能）

## 产品边界
**做什么**：
- `jex audit` 检查项目依赖是否有已知安全漏洞
- 显示漏洞详情（CVE 编号、严重程度、受影响版本）
- 支持修复建议（升级到安全版本）
- 显示检查结果摘要（漏洞数量、严重程度分布）

**不做什么**：
- 不自动修复漏洞（需用户确认）
- 不检查项目代码安全性（仅检查依赖）
- 不提供漏洞数据库订阅（使用公开数据源）

## 子任务详细设计

### 1 漏洞查询核心
- **功能目标**：实现依赖漏洞查询和分析逻辑
- **文件结构**：`crates/jex-core/src/audit.rs`
- **接口设计**：
  - `pub fn check_vulnerabilities() -> Result<Vec<Vulnerability>>`
  - `pub fn get_fix_suggestion(vuln: &Vulnerability) -> Option<String>`
  - `struct Vulnerability { group, artifact, current_version, cve_id, severity, description, fixed_version }`
- **设计要点**：
  - 读取 jex.lock.toml 获取项目依赖
  - 查询 OSV (Open Source Vulnerabilities) 数据库获取漏洞信息
  - 解析漏洞详情和修复建议
  - 支持多种严重程度（Critical/High/Medium/Low）
- **测试标准**：漏洞查询、严重程度分类、修复建议 3 个用例
- **提交信息**：`feat: add dependency vulnerability check with OSV integration`

### 2 CLI 集成
- **功能目标**：注册 `jex audit` 子命令
- **文件结构**：`crates/jex-cli/src/main.rs`
- **接口设计**：
  - `jex audit` 检查所有依赖漏洞
  - `jex audit --json` 输出 JSON 格式报告
- **设计要点**：
  - AuditArgs 结构体（支持 --json 标志）
  - 表格输出显示漏洞详情
  - 颜色编码严重程度（红色=Critical/High，黄色=Medium，绿色=Low）
- **测试标准**：命令解析测试
- **提交信息**：`feat: add jex audit CLI command with JSON output support`

### 3 报告生成
- **功能目标**：生成漏洞检查报告
- **文件结构**：`crates/jex-core/src/audit.rs`
- **接口设计**：
  - 终端输出：彩色表格，按严重程度排序
  - JSON 输出：结构化数据，便于集成
- **设计要点**：
  - 漏洞按严重程度排序（Critical > High > Medium > Low）
  - 显示漏洞摘要（总数、各严重程度数量）
  - 提供修复建议（升级到安全版本）
- **测试标准**：终端输出、JSON 输出 2 个用例
- **提交信息**：`feat: implement vulnerability report generation with terminal and JSON output`
