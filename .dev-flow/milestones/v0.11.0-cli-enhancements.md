# v0.11.0: CLI 增强

## Context
Phase 0–2 全部完成（v0.2.0–v0.7.0），Phase 3 已完成脚本模式（v0.9.0）和自更新（v0.10.0）。本里程碑补全 CLI 体验的最后几块拼图：补全 stub 命令、添加交互式 REPL、支持 shell 自动补全，标志着 jex 功能完备。

版本类型：minor（新功能）

## 产品边界

### 做什么
- `jex build` 独立编译命令（从 `run` 中提取编译逻辑）
- `jex analyze` 依赖分析（未使用 / 未声明检测）
- `jex repl` 交互式 Java 代码求值（基于 jshell）
- `jex completions` shell 自动补全生成（bash/zsh/fish/powershell）

### 不做什么
- 不做热重载（watch mode），留给后续里程碑
- 不做 monorepo 多模块支持
- 不做 IDE 集成
- 不做 `jex import`（从 pom.xml 导入），留给后续里程碑

## 子任务详细设计

### 1 `jex build` 独立编译命令

- **功能目标**：提供独立的编译命令，将 `jex run` 中的编译逻辑提取为可复用的 `jex build`，支持增量编译和编译选项
- **文件结构**
  - 修改 `crates/jex-cli/src/main.rs`：将 `Commands::Build` 从 `planned()` 改为实际调用
  - 修改 `crates/jex-core/src/run.rs`：提取编译逻辑为 `pub fn compile()` 公开函数
  - 修改 `crates/jex-core/src/lib.rs`：导出新函数
- **接口设计**
  - 命令：`jex build [--release] [--clean]`
    - `--release`：Release 模式编译（未来用）
    - `--clean`：清理编译缓存后重新编译
  - 返回值：编译成功输出 class 目录路径，失败输出错误信息
  - 编译逻辑复用 `run.rs` 中的 `compile_java` 内部函数
- **交互设计**
  - 编译中显示进度：` Compiling src/Main.java...`
  - 成功：`✅ Build complete → .jex/build/classes/`
  - 失败：显示编译错误详情
- **后端流程**
  1. 读取 jex.toml 获取依赖 classpath
  2. 收集 src/ 下所有 .java 文件
  3. 调用 javac 编译，输出到 .jex/build/classes/
  4. 增量编译：对比 .java 和 .class 时间戳，只编译变更文件
- **测试标准**
  - 单元测试：编译单文件项目成功
  - 单元测试：增量编译只编译变更文件
  - 单元测试：`--clean` 清理后全量编译
  - 集成测试：编译含依赖的项目（classpath 正确传递）
- **提交信息**：`feat: add jex build command with incremental compilation`

### 2 `jex analyze` 依赖分析

- **功能目标**：分析项目中未使用的依赖和未声明的依赖引用，帮助开发者保持依赖清单干净
- **文件结构**
  - 修改 `crates/jex-cli/src/main.rs`：将 `Commands::Analyze` 从 `planned()` 改为实际调用
  - 新建 `crates/jex-core/src/analyze.rs`：依赖分析逻辑
  - 修改 `crates/jex-core/src/lib.rs`：导出 analyze 模块
- **接口设计**
  - 命令：`jex analyze`
  - 输出格式：
    ```
    📊 依赖分析

    未使用的依赖（声明但未引用）：
      ⚠ com.google.code.gson:gson — 未在源码中发现 import

    未声明的依赖（引用但未声明）：
      ❌ org.apache.commons:commons-lang3 — 在 Main.java 中引用但未在 jex.toml 中声明

    ✅ 已分析 5 个依赖，2 个问题
    ```
- **交互设计**：终端彩色输出，未使用用 ⚠ 警告，未声明用 ❌ 错误
- **后端流程**
  1. 读取 jex.toml 中声明的所有依赖（group:artifact）
  2. 扫描 src/ 下所有 .java 文件的 import 语句
  3. 解析 import 为 Maven 坐标（通过 search API 或本地映射）
  4. 对比两集合，找出差异
  5. 输出分析结果
- **测试标准**
  - 单元测试：检测未使用的依赖
  - 单元测试：检测未声明的依赖
  - 单元测试：全部匹配时输出清洁报告
  - 边界测试：空项目、无依赖项目
- **提交信息**：`feat: add jex analyze for unused/undeclared dependency detection`

### 3 `jex repl` 交互式求值

- **功能目标**：提供交互式 Java 代码求值环境，基于 JDK 自带的 jshell，支持多行输入、历史记录、自动加载项目依赖
- **文件结构**
  - 修改 `crates/jex-cli/src/main.rs`：添加 `Commands::Repl` 子命令
  - 新建 `crates/jex-core/src/repl.rs`：REPL 核心逻辑
  - 修改 `crates/jex-core/src/lib.rs`：导出 repl 模块
- **接口设计**
  - 命令：`jex repl [--class-only]`
    - `--class-only`：仅加载已编译的 class（不加载依赖 jar）
  - REPL 启动时自动注入项目 classpath（从 jex.toml 解析）
  - 退出：输入 `/exit`、`/quit` 或 Ctrl+D
- **交互设计**
  ```
  jex repl v0.11.0
  项目依赖已加载（3 个 jar）
  输入 Java 代码，/exit 退出

  jex> System.out.println("Hello!");
  Hello!

  jex> import java.util.List;
  jex> List.of(1,2,3).stream().map(x -> x*2).toList()
  [2, 4, 6]

  jex> /exit
  👋
  ```
- **后端流程**
  1. 读取 jex.toml，解析依赖 classpath
  2. 启动 jshell 进程，传递 `--classpath` 参数
  3. 通过 stdin/stdout 与 jshell 交互
  4. 包装 jshell 输出，添加 jex 品牌提示
  5. 支持多行输入（检测未闭合的括号/引号）
- **测试标准**
  - 单元测试：classpath 构建正确
  - 单元测试：退出命令识别
  - 集成测试：启动 REPL 并执行简单表达式
  - 边界测试：无 JDK 时的错误提示
- **提交信息**：`feat: add jex repl interactive Java evaluation`

### 4 `jex completions` shell 补全

- **功能目标**：生成 shell 自动补全脚本，支持 bash/zsh/fish/powershell，利用 clap 内置的补全生成能力
- **文件结构**
  - 修改 `crates/jex-cli/src/main.rs`：添加 `Commands::Completions` 子命令
  - 新建 `crates/jex-cli/src/completions.rs`：补全生成逻辑
- **接口设计**
  - 命令：`jex completions <SHELL>`
    - `<SHELL>`：bash | zsh | fish | powershell
  - 输出：将补全脚本写入 stdout（用户可重定向到文件）
- **交互设计**
  ```bash
  # bash
  jex completions bash > ~/.local/share/bash-completion/completions/jex

  # zsh
  jex completions zsh > ~/.zsh/completions/_jex

  # fish
  jex completions fish > ~/.config/fish/completions/jex.fish

  # powershell
  jex completions powershell > $PROFILE\jex completions.ps1
  ```
- **后端流程**
  1. 使用 clap 的 `Command::generate_completions()` 生成补全脚本
  2. 根据 shell 类型输出对应格式
  3. 包含子命令、参数、别名的补全
- **测试标准**
  - 单元测试：生成 4 种 shell 的补全脚本不 panic
  - 集成测试：生成的 bash 补全可被 bash 加载
- **提交信息**：`feat: add jex completions for bash/zsh/fish/powershell`

## 设计核对点

- `jex build` 复用 `run.rs` 编译逻辑，避免代码重复
- `jex analyze` 依赖解析复用已有的 resolver/search 模块
- `jex repl` 基于 jshell（JDK 自带），不引入新外部依赖
- `jex completions` 利用 clap 原生能力，不写手动生成逻辑
- 所有新命令遵循现有 CLI 风格（clap + anyhow 错误处理）
