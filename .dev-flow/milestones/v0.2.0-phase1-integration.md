# v0.2.0: Phase 1 — 整合版（v1）

## Context
Phase 0（地基）已完成：cargo init + clap 骨架、~/.jex 配置目录、错误体系、Coursier 自检。
Phase 1 是第一个功能交付里程碑，整合现有命令行/服务（Coursier + Adoptium + jstat/jcmd），实现完整的「版本管理 → 依赖 → 运行 → 诊断」主线。

版本类型：minor（新功能，向后兼容）

## 产品边界
**本阶段做什么：**
- `jex jdk` 子命令：install / use / list / which / doctor
- `jex init / add / remove / update` 依赖管理
- `jex run` 一键运行（解析 → 编译 → 运行）
- `jex search` Maven Central 搜索
- `jex java gc / threads` 诊断
- `jex export maven` 导出 pom.xml

**不做什么：**
- 不内嵌 Coursier（继续用 shell cs）
- 不实现火焰图/JFR（Phase 2）
- 不实现 import pom（Phase 2）

## 子任务详细设计

### 1 JDK 版本管理（mise 模型）

- **功能目标**：实现 `jex jdk` 子命令，支持 JDK 安装、切换、列表、路径查询、一致性校验
- **文件结构**：创建 `src/jdk.rs`，修改 `src/main.rs`（Jdk 子命令路由）
- **接口设计**：
  - `jex jdk install <ver>`：下载并解压 Temurin 到 `~/.jex/jdks/<ver>/`
  - `jex jdk use <ver>`：写项目 `.jex-version` 或全局 `~/.jex/jdk-current`
  - `jex jdk list`：列出已装版本（✔）与当前版本（→）
  - `jex jdk which`：打印当前生效 JDK 的 `JAVA_HOME`
  - `jex jdk doctor`：检查项目声明 vs 实际已装是否一致
- **后端流程**：
  1. 调用 Adoptium API `GET https://api.adoptium.net/v3/info/available_releases` 获取可装版本
  2. 下载：`GET https://api.adoptium.net/v3/binary/latest/{feature}/ga/{os}/{arch}/jdk/hotspot/normal/eclipse`
  3. 解压到 `~/.jex/jdks/<ver>/`
  4. 版本切换：写 `.jex-version`（项目级）或 `~/.jex/jdk-current`（全局）
  5. 生效优先级：项目 `.jex-version` → 全局 `~/.jex/jdk-current` → 系统 `java`
- **测试标准**：`cargo test` 通过
- **提交信息**：`feat(jdk): implement JDK version management (mise model)`

### 2 依赖管理（init/add/remove/update + 锁文件）

- **功能目标**：实现 `jex init / add / remove / update` 子命令，管理 `jex.toml` 和 `jex.lock.toml`
- **文件结构**：创建 `src/deps.rs`，修改 `src/main.rs`（Add/Remove/Update 子命令路由）
- **接口设计**：
  - `jex init [--name X]`：生成 `jex.toml`（已在 config.rs 实现，需增强）
  - `jex add <coord> [--version V]`：添加依赖到 `jex.toml [dependencies]`，调用 Coursier 解析，更新 `jex.lock.toml`
  - `jex remove <coord>`：从 `jex.toml` 删除依赖，重算锁文件
  - `jex update [coord]`：更新依赖版本
- **后端流程**：
  1. 读取/写入 `jex.toml`（TOML 解析）
  2. 调用 Coursier：`cs fetch -p <g:a:v> --cache ~/.jex/cache` 获取 classpath
  3. 生成 `jex.lock.toml`（flat 全量依赖树）
  4. 编译缓存：基于源文件 hash + 依赖 hash
- **测试标准**：`cargo test` 通过
- **提交信息**：`feat(deps): implement dependency management with lock file`

### 3 依赖搜索（Maven Central Solr API）

- **功能目标**：实现 `jex search` 子命令，查询 Maven Central
- **文件结构**：创建 `src/search.rs`，修改 `src/main.rs`（Search 子命令路由）
- **接口设计**：
  - `jex search <keyword>`：查 Maven Central Solr API，返回 `groupId:artifactId` + 最新版本 + 描述
  - `jex search <g:a> --versions`：列出某 artifact 的全部可用版本
- **后端流程**：
  1. 调用 `https://search.maven.org/solrsearch/select?q=<keyword>&rows=20&wt=json`
  2. 解析 JSON 响应，提取坐标和版本
  3. 格式化输出
- **测试标准**：`cargo test` 通过
- **提交信息**：`feat(search): implement Maven Central search`

### 4 一键运行（解析 → 编译 → 运行 + 缓存）

- **功能目标**：实现 `jex run` 子命令，完成完整的「依赖 → 编译 → 运行」流程
- **文件结构**：创建 `src/run.rs`，修改 `src/main.rs`（Run 子命令路由）
- **接口设计**：
  - `jex run <file.java> [-- <args>]`：自动解析依赖 → 拼 classpath → `javac` → `java`
  - `jex run`（无参）：用 `jex.toml [project].main` 指定的入口
- **后端流程**：
  1. 读 `jex.toml` + `jex.lock.toml`
  2. 用 `~/.jex/cache` 里的 jar 拼 classpath
  3. 编译：`javac -cp <cp> -d .jex-build`（基于 hash 跳过重复编译）
  4. 运行：`java -cp .jex-build:<cp> <MainClass> [args]`
  5. JDK 取优先级：项目 `.jex-version` → 全局 `~/.jex/jdk-current` → 系统 `java`
- **测试标准**：`cargo test` 通过
- **提交信息**：`feat(run): implement one-click run with compilation cache`

### 5 诊断核心（gc/threads）

- **功能目标**：实现 `jex java gc / threads` 子命令，封装 jstat/jcmd
- **文件结构**：创建 `src/diag.rs`，修改 `src/main.rs`（Java 子命令路由）
- **接口设计**：
  - `jex java gc <pid>`：`jstat -gcutil` 清晰展示 + 列解释
  - `jex java threads <pid>`：`jcmd Thread.print` 清晰展示（线程状态、死锁高亮）
- **后端流程**：
  1. 调用 `jstat -gcutil <pid> 1000`，解析文本输出
  2. 调用 `jcmd <pid> Thread.print`，解析文本输出
  3. 格式化为可读报告
- **测试标准**：`cargo test` 通过
- **提交信息**：`feat(diag): implement core diagnostics (gc/threads)`

### 6 生态互通（export maven）

- **功能目标**：实现 `jex export maven` 子命令，生成 pom.xml
- **文件结构**：创建 `src/export.rs`，修改 `src/main.rs`（Export 子命令路由）
- **接口设计**：
  - `jex export maven [--out pom.xml]`：读 `jex.lock.toml` → 生成 `pom.xml`
- **后端流程**：
  1. 读 `jex.lock.toml` 的扁平依赖列表
  2. 生成 `pom.xml`：`groupId` = `local.<project.name>`，`artifactId` = `[project].name`，`version` = `0.1.0`
  3. `<dependencies>` 逐条 `<dependency><groupId><artifactId><version>`
  4. **有损**：scope 全默认 `compile`，不处理 exclusions
- **测试标准**：`cargo test` 通过
- **提交信息**：`feat(export): implement Maven pom.xml export`
