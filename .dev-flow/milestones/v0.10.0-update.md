# v0.10.0: 自更新

## Context
Phase 3（扩展/远期）进行中。v0.8.0 完成代码格式化，v0.9.0 完成脚本模式。v0.10.0 实现自更新能力，让用户能一键更新 jex 二进制。
版本类型：minor（新增功能）

## 产品边界
本阶段做什么：
- 提供 `jex self update` 命令检查并更新到最新版本
- 支持 `--check` 模式仅检查不更新
- 跨平台支持（Linux/macOS x86_64/aarch64）
- 原子替换（下载到临时文件 → rename 替换）

本阶段不做什么：
- 不做自动更新提示（CLI 启动时检查）
- 不做版本回滚
- 不做增量更新（全量替换二进制）

## 子任务详细设计

### 1 版本检查 API

- **功能目标**：通过 GitHub Releases API 获取最新版本信息
- **文件结构**：新建 `crates/jex-core/src/update.rs`
- **接口设计**：
  ```rust
  pub struct UpdateInfo {
      pub latest_version: String,
      pub download_url: String,
      pub release_notes: String,
  }

  pub fn check_latest() -> Result<UpdateInfo>;
  pub fn needs_update(current: &str, latest: &str) -> bool;
  ```
- **后端流程**：请求 `https://api.github.com/repos/JeeLin/jex/releases/latest` → 解析 JSON → 提取 tag_name、assets[].browser_download_url
- **测试标准**：单元测试覆盖版本比较逻辑（semver）、JSON 解析
- **提交信息**：`feat(update): add GitHub Releases version check API`

### 2 下载管理

- **功能目标**：下载匹配平台的 jex 二进制到临时目录
- **文件结构**：修改 `crates/jex-core/src/update.rs`
- **接口设计**：
  ```rust
  pub fn download_binary(url: &str, dest: &Path) -> Result<()>;
  pub fn detect_platform() -> Result<(String, String)>; // (os, arch)
  ```
- **平台检测**：
  - Linux: `x86_64-unknown-linux-gnu` / `aarch64-unknown-linux-gnu`
  - macOS: `x86_64-apple-darwin` / `aarch64-apple-darwin`
  - Windows: `x86_64-pc-windows-msvc` / `aarch64-pc-windows-msvc`
- **下载策略**：使用 reqwest（已有依赖）流式下载，显示进度
- **测试标准**：单元测试覆盖平台检测逻辑
- **提交信息**：`feat(update): add cross-platform binary download`

### 3 CLI 集成

- **功能目标**：注册 `jex self update` 子命令
- **文件结构**：修改 `crates/jex-cli/src/main.rs`
- **接口设计**：
  ```rust
  // jex self update          —— 检查并更新
  // jex self update --check  —— 仅检查
  ```
- **交互流程**：
  1. 检查最新版本
  2. 比较当前版本
  3. 若需更新：显示版本差异 → 确认 → 下载 → 替换
  4. 若已是最新：显示 "已是最新版本"
- **测试标准**：CLI 集成测试
- **提交信息**：`feat(cli): add jex self update command`

### 4 原子更新 + 测试

- **功能目标**：安全替换当前二进制，确保更新过程不中断
- **文件结构**：修改 `crates/jex-core/src/update.rs`
- **原子替换策略**：
  1. 下载到临时文件 `{current_path}.tmp`
  2. 设置可执行权限（Unix: `chmod +x`）
  3. 原子替换：`std::fs::rename(tmp_path, current_path)`
  4. 清理旧版本
- **错误处理**：替换失败时恢复原文件，显示错误信息
- **测试标准**：单元测试覆盖替换逻辑、权限设置
- **提交信息**：`feat(update): implement atomic binary replacement`

## 设计核对点

- [ ] GitHub API 请求是否正确处理 rate limit
- [ ] 下载进度显示是否友好
- [ ] 原子替换是否在所有平台可靠

- [ ] 版本比较是否遵循 semver 规范
